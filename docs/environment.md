Loading the FIT at `${kernel_addr_r}` fails with `ERROR: new format image overwritten - must RESET the board to recover` because the kernel `load` address is the same — use `0x44000000`. Flipping byte 5000000 from `e1` to `ff` → `sha256 error!` / `Bad hash value for 'hash-1' hash node in 'kernel-1' image node` / `Bad Data Hash` / `ERROR -2: can't get kernel image!` |
| FIT signing (lesson 36) | `openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:2048` + `openssl req -batch -new -x509` → `keys/dev.key` **1 704 B** (`-rw-------`), `keys/dev.crt` **1 127 B**. Put `signature-1 { algo = "sha256,rsa2048"; key-name-hint = "dev"; sign-images = "kernel", "fdt", "ramdisk"; }` inside `conf-1`, then `mkimage -f kernel-signed.its -k keys -K control.dtb -r` (control.dtb = a copy of the `-bios` DTB dump). control.dtb grows 1 048 576 → **1 049 984 B** and gains `/signature/key-dev` with `required = "conf"`, `rsa,num-bits = <0x800>`, `rsa,exponent = <0x00 0x10001>`. QEMU `-dtb control.dtb` hands it to U-Boot as the control FDT (works because `CONFIG_OF_BOARD=y`). Signed image → `Verifying Hash Integrity ... sha256,rsa2048:dev+ OK` three times, then boots; the **intact but unsigned** image on the same U-Boot → `No 'signature' subnode found for 'conf-1' config node` / `Failed to verify required signature 'key-dev'` / `Bad Data Hash` / `ERROR -2` |
